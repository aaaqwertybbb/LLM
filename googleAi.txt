> Explain the difference between splitting by individual letters versus whole words

< When building an LLM, choosing whether to split text by individual letters (Character-level) or whole words (Word-level) is a foundational design choice. It determines how the AI "sees" language and dictates its vocabulary size.
<
< # The Core Difference
< - Character-Level: The AI looks at text one letter or punctuation mark at a time (e.g., h, e, l, l, o)
< - Word-Level: The AI looks at text one complete word at a time (e.g., hello)
<
< # Direct Comparison
< (A chart comparing): 'Feature' - 'Character-Level (Letters)' - 'Word-Level (Whole Words)':
<
< Feature                       | Character-Level (Letters)                                                                                            | Word-Level (Whole Words)
< -----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
< Vocabulary Size               | Extremely Small (usually ~65 to 100 characters including space, punctuation, and capitals).                          | Massive (tens of thousands to millions of unique words).
< Out-of-Vocabulary (OOV) Words | Impossible. The AI can spell anything because it knows the entire alphabet. It will never see an "unknown" word.     | Highly Likely. If a user inputs a slang word or a brand name the model wasn't trained on, it breaks.
< Memory & Computation          | Low RAM needed because the lookup table is tiny. However, sentences become very long (many tokens per sentence).     | High RAM needed to store a massive dictionary. Sentences are shorter (fewer tokens per sentence).
< Spelling Skills               | The AI must learn how to spell words from scratch by guessing the next letter. It often invents fake words early on. | The AI never misspells because it only operates on perfect, pre-existing words.
< 
< # Why Modern LLMs Choose a Middle Ground
< |
< If you look at production models like Gemini or GPT-4, they actually use a hybrid approach called Subword Tokenization (like Byte-Pair Encoding).
< |
< - It splits common words into whole pieces (e.g., hello) but breaks rare or complex words into smaller letter chunks (e.g., pre + conditioned).
< - This gives them the best of both worlds: a manageable vocabulary size and the ability to handle brand-new or misspelled words.

# Number of independent text sequences to process in parallel
batch_size = 4 

def get_batch(split):
    # Select whether we are pulling from the training or validation set
    data = train_data if split == 'train' else val_data
    
    # Generate random starting points in the data array
    # We subtract block_size so we don't accidentally overflow past the end of the text

    x_batch = torch.stack([data[i:i+block_size] for i in ix])
    y_batch = torch.stack([data[i+1:i+block_size+1] for i in ix])
